# Review-provenance ledger

**Snapshot date: 2026-07-10.** A standing record of *which* surface was adversarially reviewed, *at what depth*, and *when* — so a **stale, source-only "no finding" cannot masquerade as durable assurance**. A green review from three weeks ago that only *read* the source is weaker evidence than one that *ran the tool* yesterday; this ledger makes that difference first-class instead of invisible. It operationalizes the review-provenance field the FV adversarial-review playbook names (`docs/verification/fv-adversarial-review-playbook.md` line ~189).

Pairs with [`THREAT_CLAIM_MAP.md`](THREAT_CLAIM_MAP.md) (the `Last review` column there points here).

## Depth legend (weakest → strongest)

| Depth | What it means | Epistemic weight |
|---|---|---|
| `source-read` | reviewer READ the code/model/proof; no live build/run | weakest — a stale source-read is the exact trap this ledger guards |
| `manual-audit` | human/LLM adversarial audit that traced concrete exploit paths (found real HIGHs) | strong for what it looked at; coverage is by-hand, not exhaustive |
| `executing` | the tool was actually RUN (proverif/tamarin/kani/lake/forge), verdicts read from output | strong — binds the artifact, not a reading of it |
| `mutation-verified` | an anti-vacuity mutation was shown to flip the verdict (proof is non-hollow) | strongest software tier — the gate is proven load-bearing |
| `silicon-E2E` | validated on real STM32U585 / SE hardware | strongest for hardware-bound properties |

The historical ledger below is retained verbatim. The current full-stack round
is recorded separately because it has two mutually withheld first passes, two
symmetric cross reports, and one coordinator synthesis rather than a single
