It closes the coverage-completeness blind spot: per-theorem gates can only tell you a claim is *hollow*; they cannot tell you a threat has **no claim at all**, because there is no theorem to turn red. This map is that missing view.

> **Not a source of truth for what is *claimable*** — that is [`THE_CLAIM.md`](THE_CLAIM.md). This is a coverage index; every COVERED/PARTIAL row routes to the artifact that owns the proof. Where it could drift from `ASSURANCE_CASE.md` / `THE_CLAIM.md`, defer to those.

## How this was built (and its own honesty discipline)

A background workflow enumerated the threat surface from four independent readers (`docs/security/threat-model.md` as the SSOT + the 9 CLAUDE.md invariants + ship-blockers + the 9 `docs/security/adversarial-review/` family playbooks → **62 threats + 85 attack-classes**), the claim/coverage inventory (**62 claims** across Lean / Halmos-Kontrol / Kani / protocol models / silicon-E2E / host-render / gates), and the review-round inventory (**24 rounds**, see [`REVIEW_PROVENANCE.md`](REVIEW_PROVENANCE.md)). These were reconciled into **61 surfaces**.

The failure modes are **asymmetric**: a wrongly-**COVERED** row is *false assurance* (the exact thing this doc exists to kill); a wrongly-**UNCLAIMED** row is merely conservative. So **every** COVERED/PARTIAL mapping was adversarially cite-verified — an independent agent resolved the cited `file:line` / theorem / make-target and downgraded any citation that did not genuinely cover *that* threat. The verification caught **8 mis-citations** (folded in below as downgrades/re-anchors) and, on finalize, one wrongly-**UNCLAIMED** row (`S-NS-TOCTOU`, which *is* Kani-covered). When a citation could not be firmly resolved the row was left PARTIAL/UNCLAIMED, never COVERED.

## Legend

**Verdict** — ✅ COVERED: a resolved claim genuinely covers the threat · 🟡 PARTIAL: real but incomplete coverage (one layer only — e.g. model proven, no model→deployed bridge; or a positive test, not a ∀-proof) · 🔴 UNCLAIMED: in-scope threat with **no covering claim** (the rows that matter most) · ⚪ OUT-OF-SCOPE: deliberately outside the assurance stack (physical/coercion/CRQC/novel-crypto-break/silicon-lab or a named ship-blocker), listed so the boundary is explicit, not silent.

**Evidence** — `K` kernel-proven Lean ∀ · `B` bytecode-symbolic (Halmos/Kontrol) · `C` corpus/KAT/Kani-bounded · `T` cited-TCB · `silicon-E2E` on-hardware test · `host-test` render/decode host test · `gate` CI anti-vacuity/enforcement gate · `audit` manual/LLM review (see the same tiers in `ASSURANCE_CASE.md` §0).

**Coverage summary:** 61 surfaces — **4 COVERED · 30 PARTIAL · 1 UNCLAIMED · 26 OUT-OF-SCOPE**.
