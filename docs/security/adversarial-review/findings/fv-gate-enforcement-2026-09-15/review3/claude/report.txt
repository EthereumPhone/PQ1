- MEDIUM scripts/check_gate_enforcement.py:692 — The completeness check can match the wrong target name. Its pattern `SOUNDNESS_TARGET = \bmake\b[^\n]*?\b(verify-[a-z0-9-]+|kani|miri)\b` stops at a word boundary, and `-` counts as one. So `make kani-heavy` is recorded as `kani`, and `make miri-extra` as `miri`. The consequence: a workflow could run a new target that starts with `kani-` or `miri-`, and completeness would count it as the registered `kani`/`miri` gate instead of flagging it as unregistered. Evidence: running `SOUNDNESS_TARGET.finditer('make kani-heavy')` gives `['kani']`, and `'make miri-extra'` gives `['miri']`. This line predates this change, and no live workflow is affected today, so it does not block the merge. Smallest fix: use the same lookarounds `invokes_target` uses, i.e. `(?<![A-Za-z0-9_-])(verify-[a-z0-9-]+|kani|miri)(?![A-Za-z0-9_.-])`, and add a control for `make kani-other`.
