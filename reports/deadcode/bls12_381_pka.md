## Summary
`bls12_381_pka` is a **vendored fork** of `zkcrypto/bls12_381` v0.8.0, as
documented in `UPSTREAM.md`. The crate's explicit maintenance contract is
to remain byte-identical to upstream 0.8.0 except for the documented
`pka`-feature additions (`Fp::mul_pka`, the `bls12_381_pka_mont_mul`
extern hook, and a couple of `#[cfg(feature = "pka")]` guards in
`fp.rs`/`fp2.rs`). The whole point of preserving even seemingly unused
items (helper functions, `notes/` modules, `Cargo.toml.orig`, upstream
test scaffolding) is so future upstream pulls can be diffed cleanly with
`diff -ruN` per the documented "How to pull upstream changes" workflow.
Removing dead-looking-but-upstream code here would be net-negative: it
would burn maintenance cost on every future rebase against zkcrypto.

Verdict: **no deletions applied.** Any apparent dead code in this crate
is upstream code that must be kept verbatim. The single shipping
modification (`pka` feature) is live under `pka-accel,stm32u585` in the
secure-world build (`secure/Cargo.toml` wires `bls12_381_pka/pka`; see
`secure/src/hw/pka.rs` for the `bls12_381_pka_mont_mul` symbol).
