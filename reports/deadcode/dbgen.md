## Summary

This slice was already thoroughly cleaned by the readability pass logged
in `reports/readability/dbgen.md` (2026-05-14): `poseidon_bytes`, the
`_assert_record_shape` hacks, the unused `leaves_fields` accumulator,
and a redundant `leaf_hashes.clone()` in `erc20.rs` were already gone.
Only two leftovers remained — one residual `leaf_hashes.clone()` in
`vks.rs` and a stale `Writes:`/`runtime parser is in:` block in the
`main.rs` module docstring that still pointed at pre-port `secure/`
paths instead of the actual `nonsecure/` outputs. Both removed/fixed
here. The crate has no `unsafe`, no dev-only feature gates, no
cross-world consumers — every `pub` is internal to the bin crate — so
the audit surface is small and behaviour-preserving deletions are
straightforward. No further dead code identified.

  `tools/export_poseidon_constants.js`) carries `pub const N_CONSTANTS`

  this slice.

## Skipped
- Generated table re-exported via `#[path = "../../secure/src/zk/generated/poseidon_constants.rs"]` — `#[allow(dead_code)]` on the mod import is intentional (dbgen only consumes a subset of the per-arity constants); leaving as-is.
- `poseidon_fields` dispatch arms for arities 3, 5, 7 — invoked only by the test vectors in `poseidon::tests`, but those are bucket 2 (intentional dev infrastructure providing a JS-anchored reference implementation) and stay.
- The `assert!(!leaves.is_empty())` panics in `MerkleTree::build` and `PoseidonMerkleTree::build` — flagged as "belt-and-braces" by the readability pass; left untouched, callers already pre-check.
