## Summary
The slice is clean. Every public item declared in `fsbl/src/**` has a
live caller on the boot path rooted at `main::main()`. The few borderline
items found are intentional infrastructure — wire-format parity with the
secure-world `boot_state` parser, an architectural-rationale comment
block on the `sphincs-c10` direct dep, and the `#[allow(dead_code)]`
`VENDOR_PK_FPR` constant referenced by the security-review handoff. None
qualify as dead-code-bucket-1/3/4/5/6, so no deletions are applied.

## Recommendations NOT applied

1. **`BootState::last_good_version` (`src/boot_state.rs:24,51,59`).**
   The field is parsed off-flash and populated into the struct, but the
   FSBL itself only consults `active_slot`. Removing the field would
   tighten the Rust API but break the in-source documentation contract
   ("Mirrors the layout in `secure/src/hw/boot_state.rs`"), which is the
   reason both modules define a struct of the same shape. Keep until
   either (a) the layout comment is updated to say "FSBL reads only
   `active_slot`", or (b) a future FSBL revision actually consumes the
   version for rollback decisions.

2. **Redundant direct `sphincs-c10` runtime dep (`Cargo.toml:13`).**
   `fw-manifest` already pulls `sphincs-c10` transitively with the same
   feature set, so the direct entry is technically redundant. The
   accompanying multi-line comment, however, encodes a deliberate
   architectural decision (software SHA-256 vs `hw-sha256`, Verify-only
   posture, byte-compatibility with the Solidity verifier). Removing the
   dep line would orphan that comment; leaving it costs nothing.

3. **`vendor_pubkey::VENDOR_PK_FPR` (`build.rs:109` → `OUT_DIR/vendor_pubkey_bytes.rs`).**
   The const is generated and held under `#[allow(dead_code)]` with the
   stated intent of letting `size` / `objdump` show the vendor
   fingerprint in the linked FSBL. As a plain `pub const` without
   `#[used]`, the compiler will in fact omit it from the linked image
   unless referenced; the rationale in the comment is therefore a touch
   optimistic. `docs/security-review-2026-05.md:109` cites
   `vendor_pubkey::VENDOR_PK_FPR` as the target of a future runtime
   self-test, so the const is intentional forward-looking infra. Leave
   it; the `pub use` in `vendor_pubkey.rs` should be widened to include
   `VENDOR_PK_FPR` (and a `#[used]` static added) when the self-test
   lands.
